# Протокол lan-share v1

Все числа big-endian. Транспорт: TCP. Обнаружение: UDP (см. ниже).

## 1. Рукопожатие (открытым текстом, JSON с префиксом длины u32)

```
Отправитель (A)                              Получатель (B)
  {"v":1, "X": hex(x_msg)}      ───────────►
                                ◄───────────  {"v":1, "Y": hex(y_msg), "name": ...}
  {"mac": confirm_A}            ───────────►   проверка; при несовпадении - разрыв
                                ◄───────────  {"mac": confirm_B}
```

**SPAKE2** в подгруппе простого порядка q = (p-1)/2 группы MODP-2048 (RFC 3526, №14), g = 4.
M и N получены хэшированием в группу (квадрат результата SHAKE-256), поэтому их
дискретные логарифмы неизвестны. Пароль `w = SHAKE256(код) mod q`.

- A: `X = g^x · M^w`, B: `Y = g^y · N^w`
- A: `K = (Y / N^w)^x`, B: `K = (X / M^w)^y`
- `TT = SHA256("lanshare-v1" ‖ X ‖ Y ‖ K ‖ w)`, элементы по 256 байт
- Ключи: `HMAC(TT, метка)` для подтверждений и для двух направлений канала
- Элементы собеседника проверяются: `1 < e < p-1` и `e^q ≡ 1 (mod p)`

Неверный код даёт другой `K`, подтверждение не сходится, соединение закрывается.
Каждая догадка кода стоит одной онлайн-попытки. После 3 неудач получатель
выпускает новый код.

## 2. Защищённый канал

Кадр: `u32 длина ‖ шифртекст ‖ HMAC-SHA256 (32 байта)`.

- Поток: `SHAKE256(enc_key ‖ u64 номер_кадра)`, XOR с данными
- Тег: `HMAC-SHA256(mac_key, u64 номер_кадра ‖ шифртекст)`, проверка ДО расшифровки
- Ключи разные для A→B и B→A; счётчик кадров защищает от повтора и перестановки
- Максимальный кадр: 64 МБ; данные файлов идут кадрами по 256 КБ

## 3. Передача (внутри канала)

1. A → B: `{"type":"manifest","sender":имя,"files":[{"path","size","sha256"}, ...]}`
2. B спрашивает пользователя (или `--yes`)
3. B → A: `{"accept":false}` либо `{"accept":true,"offsets":[...],"skip":[...]}`
   - `offsets[i]`: сколько байт файла i уже есть в `.part` (докачка)
   - `skip[i]`: файл уже есть целиком и хэш совпал, слать не надо
4. A → B: кадры с данными по порядку файлов, начиная с `offsets[i]`
5. B → A: `{"done":true,"results":[{"path","ok"}, ...]}` после проверки SHA-256

Получатель пишет в `<имя>.part`, считает SHA-256 на лету (включая уже лежащую
часть) и переименовывает файл только при совпадении хэша. Существующие
несовпадающие файлы не перезаписываются: новый получает суффикс ` (1)`.

## 4. Проверки безопасности на стороне получателя

- пути: без абсолютных, `..`, `.`, пустых компонент, `\`, `:`, нулевых байтов;
  итоговый путь проверяется на нахождение внутри папки назначения
- размеры и хэши в манифесте валидируются по типу и формату
- кадр с данными не может быть больше оставшегося размера файла
- симлинки на стороне отправителя пропускаются

## 5. Обнаружение (UDP, порт 50505)

Запрос `LANSHARE-DISCOVER/1` отправляется на multicast `239.255.77.77` и на
broadcast. Получатель отвечает unicast-ом JSON `{"name","port","v":1}`.
Это собственный протокол, а не стандартный mDNS.
